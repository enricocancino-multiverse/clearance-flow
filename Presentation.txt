1. INTRODUCTION

PRESENTER:

"Good day. We are presenting ClearanceFlow, a role-based academic clearance system.

The purpose of the system is to make clearance progress easier to understand and manage. Instead of treating every office as an unrelated step, ClearanceFlow represents requirements and their prerequisites as a directed graph. Students can see their progress, teachers can process student requirements, and administrators can manage the clearance graph.

Our project combines a Next.js and React frontend, a FastAPI backend, and a PostgreSQL database. We also use Kahn's algorithm to order requirements and detect cycles in the prerequisite graph."

6. HOW THE ALGORITHM WORKS

PRESENTER:

"The graph is a directed acyclic graph, or DAG. An arrow from A to B means A must be completed before B becomes available.

Kahn's algorithm starts by finding all nodes with no remaining prerequisites. It selects one of those nodes, adds it to the order, and removes its outgoing dependency edges. Whenever a dependent node has no prerequisites left, it becomes available. The algorithm continues until all nodes are ordered or until it detects that some nodes remain blocked by a cycle.

This is useful because a cycle would make a valid clearance order impossible. The graph validation also checks for duplicate IDs, missing endpoints, self-dependencies, and duplicate edges."

OPTIONAL GREEDY EXPLANATION:

"Where request priority ordering is used, the greedy score considers urgency such as days until an exam, completed prerequisites, and how long the request has been waiting. It chooses the highest-ranked currently available request at each step. This scoring is separate from the prerequisite ordering: Kahn's algorithm handles dependency order, while the greedy score helps rank eligible requests."


7. CODE WALKTHROUGH

PRESENTER:

"Here is a quick look at how the code is organized:

- src/app/page.tsx contains the sign-in screen, role badge, department selector, demo account shortcuts, and role-based navigation after login.
- src/lib/demoAccounts.ts defines the 11 demo identities and the shared credential-classification logic.
- src/components/StudentDashboard.tsx renders the student clearance graph and status view.
- src/components/FacultyDashboard.tsx renders teacher clearance processing and schedule management.
- src/components/AdminDashboard.tsx contains the administrator interface.
- src/lib/clearanceAlgorithms.ts contains the frontend Kahn sort and greedy-priority utilities.
- backend/app/routes/auth.py handles backend authentication and credential lookup.
- backend/app/services/kahn_service.py validates and executes the graph algorithm, using the C++ module when available and a Python fallback otherwise.
- backend/app/models contains the SQLAlchemy data models, and backend/init-db/02-seed-data.sql seeds the PostgreSQL demo data.

The frontend sends requests through the API client, and the backend checks credentials and returns an authenticated session. The page then uses that session's role to open the appropriate dashboard."

POSSIBLE QUESTIONS

Q: Where is the algorithm in your project?
A: "You can see it in two places: in the running application, open the Admin dashboard and choose the Algorithm Demo tab; in the source code, the frontend demonstration is implemented in src/lib/clearanceAlgorithms.ts and displayed by src/components/AlgorithmPlayground.tsx. The backend Kahn implementation is in backend/app/services/kahn_service.py, which calls the C++ implementation in backend/cpp_module/kahn_algorithm.cpp when that module is available, and otherwise uses its Python fallback. The request-priority greedy scoring is separate and is implemented in backend/app/routes/faculty.py."

DEMONSTRATION TIP:

If your teacher asks to see the actual algorithm, don't only describe it or show the clearance graph. Open Admin Dashboard → Algorithm Demo, then explain the source:

1. Open src/lib/clearanceAlgorithms.ts and point to runKahnSort().
2. Show how the function calculates each node's indegree (the number of prerequisites), starts with nodes whose indegree is zero, and adds newly eligible nodes as prerequisites are removed.
3. Point out cycle detection: if some nodes still have indegree after the loop, the graph contains a cycle.
4. If asked how the backend runs it, show KahnService in backend/app/services/kahn_service.py, then the C++ execute implementation in backend/cpp_module/kahn_algorithm.cpp. The service uses the C++ module if available and otherwise falls back to Python.
5. Explain the distinction: Kahn's algorithm respects prerequisite order; the greedy request score ranks requests using urgency, prerequisite progress, waiting time, and department match. The faculty request scoring is in backend/app/routes/faculty.py.

Q: Why use Kahn's algorithm?
A: It produces a topological ordering of a directed graph and can identify when a cycle makes a valid ordering impossible.

Q: What does an arrow in the graph mean?
A: The source requirement must be cleared before the destination requirement can be processed.

Q: What does the greedy priority score do?
A: It ranks eligible requests using urgency, prerequisite progress, and waiting time. It does not replace the prerequisite graph.

Q: Are the demo accounts production accounts?
A: No. They all use a shared demo password for presentation and testing. Production accounts should use secure, individually managed credentials.

Q: Does a teacher's clearance change persist across devices?
A: The current teacher clearance demo uses browser-local shared state, so it is suitable for a same-browser demonstration. A database-backed workflow with cross-device synchronization is a future integration step.
